Two non-obvious things about that shape. There is no force-push rule to write. Force is a flag, not a command, and Bash rules match by command prefix — so Bash(git push:*) already covers git push --force-with-lease=…. A separate force entry would match nothing. Prefix matching is unforgiving. The trade: any git subcommand against any path, in worktrees whose work is banked on the shadow remote and recoverable. The caveat the fix cannot retire. The refusal said auto mode classifier, not a permission rule. An allow rule normally outranks it — but I have never seen a force-push tested against one. The first gate rebase after a cast is where that gets answered, and if it still refuses, skip-permissions is the only remaining lever. v2 adds work this list does not cover yet. disable-model-invocation: true   → user only   (grill-with-docs, grill-me)
